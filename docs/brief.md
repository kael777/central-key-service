# 系統簡述（Brief）

給第一次接觸這個服務的人：五分鐘看懂它怎麼運作。

## 一句話

**中央只發鑰匙，各系統自己加解密；業務資料從不經過中央。**

```
        ┌──────────────────────────────┐
        │  E：只發鑰匙                  │
        │  公鑰分發／私鑰下發／輪替／稽核 │
        └───────┬──────┬──────┬────────┘
                │      │      │        ← 控制面（每 30 秒輪詢）
        ┌───────┘      │      └───────┐
        ▼              ▼              ▼
      A  ◀──────────▶ B ◀──────────▶ C    ← 資料面（點對點，E 不參與）
        └──────────▶ D ◀──────────┘
```

鑰匙走星形，資料走網狀。E 是發鑰匙的，不是轉資料的。

---

## 一、初始化（一次性）

1. 在 E 上產生一張 CA、四張用戶端憑證（CN 分別是 `A`、`B`、`C`、`D`），以及 E 自己的伺服器憑證
2. 在 E 的後台登記 A、B、C、D
   → E 為每個系統產生一對 P-256 金鑰
   → 公鑰明文存庫，私鑰用 `KEY_KEK` 加密後存庫
3. 把各自的憑證發給 A、B、C、D（**只給自己那張**）

此時 E 的資料庫：

| 系統 | 公鑰 | 私鑰 |
|---|---|---|
| A | 明文 | 加密（只有 E 能解） |
| B | 明文 | 加密 |
| C | 明文 | 加密 |
| D | 明文 | 加密 |

業務伺服器上只有自己的私鑰，沒有別人的。

## 二、啟動時

每台業務伺服器啟動後做兩件事：

1. 用 mTLS 連 E，取**自己的**私鑰（只取得到自己的）
2. 呼叫 `/api/v1/sync`，拿到：
   - 自己可解密的版本清單
   - 對端（B/C/D）的現行公鑰
   - 對端即將生效的公鑰（`next`）

之後每 30 秒輪詢一次，本地快取 60 秒。

## 三、一筆資料從 A 到 B

```
A 要傳「身分證號=A123456」給 B
   │
   ├─ 1. A 從快取拿 B 的公鑰（B:7）
   ├─ 2. A 本地加密：
   │      臨時金鑰對 + ECDH + HKDF + AES-256-GCM
   │      產出 KEY1.B:7.ATBZMBMG...
   ├─ 3. A 把密文放進原本的請求（URL 參數／body）
   │      → 走 A 和 B 之間原有的通道（HTTP／MQ／檔案）
   │      → E 完全不在這條路上
   └─ 4. B 收到，用自己快取的私鑰（B:7）解密
```

**E 全程看不到這筆資料。** 它只知道「B 的公鑰是哪個版本」。

## 四、每小時輪替

```
T-10m   E 為每個系統建立 pending 金鑰（B:8）
        /sync 的 next 欄位開始出現 B:8
T0      B:8 轉 active，B:7 轉 decrypt_only（緩衝 5 分鐘）
        發送方 A 最晚 60 秒內換用 B:8
T0+5m   B:7 轉 retired，私鑰銷毀
        之後用 B:7 加密的密文一律解不開（正常行為）
```

重點：**發送方最多 60 秒後改用新公鑰，剩下 4 分鐘留給訊息在路上**。

安全條件（S＝快取上限、D＝端到端延遲、C＝時鐘誤差、G＝緩衝期）：

```
S + D + C < G      60 + 120 + 10 < 300
```

## 五、E 掛掉會怎樣

| 時間 | 業務影響 |
|---|---|
| 0～60 秒 | 無影響，快取還能用 |
| 60 秒～5 分鐘 | 加解密仍可用，只是不再刷新 |
| 超過 5 分鐘 | 加密端回 `ERR_STALE`，**停止加密，不退回明文** |
| 恢復後 | 自動重新同步 |

解密端只要私鑰已快取，E 掛多久都不影響解密。

## 六、誰能看到什麼

| 東西 | A | B | C | D | E |
|---|---|---|---|---|---|
| A 的私鑰 | ✅ | ❌ | ❌ | ❌ | ✅（加密儲存） |
| B 的公鑰 | ✅ | ✅ | ✅ | ✅ | ✅ |
| A→B 的密文 | ✅ | ✅ | ❌ | ❌ | ❌ |
| 明文 | ✅ | ✅ | ❌ | ❌ | ❌ |
| 業務資料 | — | — | — | — | **從不接觸** |

## 七、新增一台伺服器

```
1. 簽一張 CN=NEW 的憑證（沿用既有 CA）
2. 後台新增 NEW（產生金鑰）
3. 把憑證給 NEW，啟動 SDK
4. 其他系統下次 /sync 就自動看到 NEW 的公鑰
```

不需要改其他系統的設定。

## 八、失敗時的行為

| 情境 | 行為 |
|---|---|
| 憑證不是自家 CA 簽的 | TLS 握手失敗，請求不進來 |
| 系統未登記 | 403（錯誤訊息為「來源 IP 不符」，實為查無系統） |
| 系統已停用 | 403，金鑰已作廢 |
| token 的 purpose 不符 | `ERR_AUTH` |
| 版本已退役 | 解密失敗（密文太舊） |
| E 不可用超過 5 分鐘 | `ERR_STALE`，停止加密 |

三條紅線：**認證失敗不重試、任何錯誤不退回明文、不回傳部分明文。**

## 名詞

| 名詞 | 意思 |
|---|---|
| 系統（system） | 一台業務伺服器，用代碼（`A`）識別，等於憑證 CN |
| kid | 版本識別碼，`A:7` 表示 A 的第 7 版金鑰 |
| active | 現行版本，可用於加密與解密 |
| pending | 已發布但未生效，只能快取公鑰 |
| decrypt_only | 舊版，僅供解密，5 分鐘後退役 |
| retired | 已退役，私鑰銷毀 |
| KEK | 包裝私鑰的主金鑰，只存在 E 的環境變數／檔案 |
